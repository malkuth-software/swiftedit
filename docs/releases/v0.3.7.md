Changes since v0.3.6:

- Rendered Markdown layout yields between batches of native text measurements.
  Escape and switching back to source cancel unfinished layout as well as
  parsing. Reopening the same cancelled source starts preparation again.
- Layout continues through a UI timer without repainting an unchanged pending
  message after every batch. Completed and cancelled views retain no preparation
  timer. Native font measurement stays on the UI thread.
- Source replacement, width changes and font-metrics changes discard partial
  geometry. Returning to a previous width while a resize is unfinished rebuilds
  the correct layout. Complete geometry is published together.
- A metrics refresh no longer erases a Markdown parsing error and presents an
  empty document as successful. Readiness diagnostics now wait for a paint of
  completed geometry rather than reporting timer completion alone.
- Native regression coverage includes routed Escape during layout, cancellation
  surviving the following UI tick, reopening the same source, and closing with
  layout unfinished. Measurements distinguish cumulative layout work, longest
  slice, complete-paint observation, native presentation, and observer gaps.

The 8 ms layout target is cooperative, not a hard limit: individual native
measurements, allocation, final sorting/index construction, cleanup and host
scheduling can exceed it. A large document with many distinct words can still
take seconds to finish layout while the UI services input between batches.
The complete responsiveness and physical dogfood audit remains open.

CSV stored formulas and menu/context-menu Convert to Value keep their existing
behavior. Large-file GUI Session integration, editable visible byte mapping,
multiple selection, native printing and Markdown print preview remain unfinished.
This release uses the frozen aaca5d0 GUI.Forms and picker SDK.

The release workflow publishes Windows x64, Linux x64 and Apple-silicon macOS
archives together after their native tests and package checks pass. macOS targets
macOS 26; the application is ad-hoc signed rather than notarized.
