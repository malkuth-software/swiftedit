Changes since v0.3.4:

- CSV viewport formulas calculate on an owned background worker. Source changes,
  scrolling and closing cancel obsolete work; results from an old source cannot
  overwrite the current viewport. Calculation scheduling stops when work ends.
- Convert to Value uses the cell's current exact result. If calculation is still
  pending, conversion waits for that worker result instead of calculating on the
  UI thread. Escape, editing, selection changes or leaving the view cancel a
  pending conversion. Both the CSV menu and cell context menu retain one-step
  Undo and preserve unrelated source bytes.
- Result publication uses a bounded queue with a reference-count budget to reduce
  repeated frame handoffs. The UI retains a two-millisecond adoption target;
  individual operations and native scheduling are not hard-deadline bounded.
- Expensive formula evaluation checks cancellation within numeric parsing, range
  traversal and aggregation. Formula errors remain explicit and preserve source.

Native tests cover calculation completion, settled-idle scheduling, navigation
during calculation, closing with work pending, both conversion commands, Undo
and formula-preserving Save. Component and native measurements, raw samples and
their limits are recorded in performance/2026-10-02-csv-worker and
performance/2026-10-02-csv-cancellation. The full responsiveness audit remains open.

Stored formulas, exact arithmetic, source encoding/endings and the traditional
single-document interface retain their existing behavior. The GUI's shared
document/session migration, large-file view, visible control-byte mapping,
multiple selection, native printing and Markdown print preview remain unfinished.
