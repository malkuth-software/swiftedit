Changes since v0.3.7:

- Updates the matching GUI.Forms and picker SDKs to the tested 6f5c854 provider
  checkpoint on Windows, Linux and macOS.
- Windows input retrieval now alternates input-preferred and ordinary queued
  work, while preserving translated characters ahead of later hardware editing
  input. The provider's controlled native A/Backspace regression verifies that
  queue ordering correction.
- Windows repaint damage now includes the complete native exposure bounds,
  addressing incomplete redraw after exposure. This is not a claim that the
  broader input-latency and physical dogfood audit is complete.
- Includes the shared document model's incremental read-only UTF-8/UTF-16 paging
  and compact identity mappings. These remain migration foundations: the GUI
  still uses its existing text widget and does not yet expose that large-file
  decoded editing surface.

The pinned archives come from successful provider native push run 37185526994,
source 6f5c854e61612fadf38c35c18d06c447c5e49e4d. All archive SHA-256 sidecars and
embedded platform/source manifests were checked before adoption. SwiftEdit is
rebuilt against the matching installed public packages, including the picker.
No existing DLL is replaced in an older application package.

The release workflow publishes Windows x64, Linux x64 and Apple-silicon macOS
downloads together only after all native build/test/package jobs pass. macOS
requires macOS 26; packages remain ad-hoc signed rather than notarized.

The expanded feature set remains in progress. GUI Session migration, mapped
editing and multiselection, native printing, Markdown print preview and the
complete responsiveness audit are still outstanding.

CSV calculation completion now waits for a later UI frame after submission,
so fast worker completion cannot bypass pending conversion cancellation.
The existing eight cancellation scenarios remain enforced. The v0.3.8 tag
is retained as a failed build checkpoint; it was not published as a release.
